# 同步会话并准备面试

左侧 **求职管理 → 已交换简历会话** 保存公司、岗位 JD 和双方沟通快照。资料保存在本机 SQLite，按当前浏览器身份隔离。

## 同步一个已交换简历的聊天

1. 升级已有安装时，在项目根目录执行 `pnpm db:migrate`。
2. 在 **BOSS 求职** 打开项目专用窗口，完成人工登录和会话检查。只读同步可使用 `BOSS_AUTOMATION=manual`。修改配置后重启 API 和 Worker。
3. 在专用窗口进入消息页，选中已经交换简历的聊天，展开岗位资料和需要保存的消息。
4. 回到 **已交换简历会话**，点击 **同步当前会话**。
5. 等待状态显示已完成。打开会话，核对公司、JD、简历交换依据、消息方向和读取时间。

同步复用 Worker 已持有的窗口，不接管日常 Chrome，不读取或导入 Cookie，不发送消息或附件。没有专用窗口、账号或会话标识不可靠、交换状态只有请求，都会停止同步。遇到登录验证或站点限制时，先人工处理，再重新发起。

页面结构无法识别时，Worker 在私有观察目录保存有界结构诊断，包含标签、类名、属性名称和子节点结构，不包含聊天正文或属性值。诊断文件不进入会话库或公开报告，用于按实际页面修正适配。

当前逐个同步选中的聊天。系统不自动遍历会话列表、不翻页补齐历史，也不在后台定时同步。每次最多保存 200 条当前 DOM 中可见的消息，页面外和未加载的记录不包含在快照内。超过上限时拒绝保存，不截断消息。

如果聊天没有完整 JD，读取器会核对当前组件或唯一同站链接中的岗位入口，在新页读取详情并保留原聊天选择。遇到限制时保留限制页面。其他页面结构或没有可靠入口时，使用 **手动补充 JD**，补充内容与站点原文分开保存。

## 查看和管理本地会话

会话列表显示最近 100 个会话，可按公司或岗位查找。相同账号、聊天和岗位组成同一个本地会话；内容未变时不重复建档，变化后保留新的快照。详情页可回看最近 100 个历史快照。

**取消同步** 阻止尚未完成的任务继续保存。**删除本地会话** 删除该会话及历史快照，同时取消当前身份未完成的会话同步。已有面试记录保留。重新发起同步仍可建立新的本地会话。

固定使用原来的浏览器和 `localhost` 入口。不同浏览器身份的数据不会自动合并。浏览器草稿备份不包含服务端会话库，数据库备份见 [SQLite 存储说明](design/sqlite-local.md)。

## 从 JD 进入备题和模拟面试

1. 打开本地会话，核对站点 JD 或补充缺失的 JD。
2. 选择简历库中的 JSON 副本。模拟面试必须选择简历。
3. 需要针对沟通内容准备时，勾选摘要选项，手动填写相关关注点。系统不默认外发整段聊天。
4. 点击 **JD 备题** 或 **模拟面试**，确认替换尚未提交的准备草稿。
5. 在准备页核对资料、选择模型并生成内容。备题可编辑后保存题库，再从题库开始练习；模拟面试沿用作答、反馈和报告流程。

启用模型生成时，JD、所选简历及勾选的摘要会发送给所选模型。进入准备页本身不会调用模型。简历文本和 JD 超出长度限制时提示整理，不静默截断。沟通内容不会被当成已验证的个人经历。

## 验证范围

隔离测试覆盖本机 Chrome、Worker、SQLite 和网页操作，使用合成会话验证同步、幂等、岗位链接补全、归属隔离、取消、删除以及带入面试草稿。运行方式：

```sh
RUN_INTEGRATION=1 pnpm exec vitest run tests/boss-inbox.test.ts tests/boss-inbox-browser.integration.test.ts
pnpm test:e2e:resumes
```

这项验收只覆盖当前版本、单个选中会话和已加载的消息窗口，不代表完整历史或其他页面版本均兼容。页面结构不匹配时会提示缺少可靠依据，不能把未完成的同步计作成功。
