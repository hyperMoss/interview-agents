# 产品定位整改开发计划

> **配套文档**：[product-positioning-refactor.md](./product-positioning-refactor.md)
> **目标**：将产品从"面试练习工具"的单点认知升级为"全流程求职面试助手"的完整定位
> **执行方式**：按 P0 → P1 → P2 分批交付，每批可独立验收

---

## 任务总览

| 批次 | 任务数 | 预估总工时 | 交付物 |
|------|--------|-----------|-------|
| P0（必改） | 4 项 | ~4h | 文案 + 2 处按钮调整 + 模式标识 |
| P1（重要） | 4 项 | ~11h | 菜单优化 + 简历库操作 + 报告按钮 + 首页引导区 |
| P2（加分） | 3 项 | ~18h | 进度提示 + 新用户引导 + 旅程可视化 |

---

## P0 批次：必改项

### P0-1 · README 与功能表格文案重写

**文件**：`README.md`

**改动清单**：

1. **首句改写**
   ```diff
   - 一个本地运行的 AI 求职与面试练习工具，集成简历管理、JD 备题、模拟面试、算法练习和 BOSS 岗位搜索与审核。
   + 从找岗位到拿 Offer，全流程 AI 求职助手，数据本地保存。覆盖 BOSS 岗位搜索与审批、简历制作、JD 备题、模拟面试、算法练习全链路。
   ```

2. **功能表格标题改写**
   ```diff
   - ## 功能特性
   + ## 覆盖求职全流程的 9 大模块
   ```

3. **功能表格排序调整**：按求职自然顺序重排，从"简历管理"开始，以"BOSS 求职 → JD 备题 → 模拟面试 → 算法练习 → 复盘"为轴。

4. **BOSS 求职功能描述改写**（按整改单 §4.2）：
   ```diff
   - 按城市、预设或自定义方向搜索，保存岗位快照、筛选依据和人工复核结果；明确批准后由 Worker 程序化发起站内沟通。
   + 按城市/方向搜索岗位，AI 核对薪资与雇佣关系，保存快照与筛选依据；人工审批后由 Worker 串行发起站内沟通；已交换简历会话可同步 JD 直接带入备题或模拟面试。
   ```

5. **JD 备题功能描述改写**（按整改单 §4.2）：
   ```diff
   - 提前生成带原文依据的题单，保留备题历史并支持失败重试，编辑后保存到题库或带入面试。
   + 基于 JD 自动生成备考题单（3-12 道），区分必备项与加分项，每题带原文依据。编辑后一键入库，或直接带入模拟面试以原题形式练习。从 BOSS 会话 JD 一键进入，历史记录可回看和重试。
   ```

6. **「第一次使用」流程说明**：在快速开始的步骤中加入 BOSS 求职路径：
   ```diff
   + 0. 也可从 **求职管理 → BOSS 求职** 搜索目标岗位，审批后同步会话 JD，直接带入下列准备流程。
     1. 进入 **面试准备**，上传或粘贴简历，填写目标岗位与 JD。
   ```

**验收**：README 中不出现"练习工具"单独描述；功能顺序体现求职全链路逻辑。

### P0-2 · 会话详情页「带入备题」「带入面试」按钮置顶

**文件**：`apps/web/src/boss-inbox-panel.tsx`

**改动要求**：

1. 在会话详情的**首屏操作区**（`<div className="inbox-actions">` 或等效容器）置顶展示两个主操作按钮：
   ```
   [→ JD 备题]   [→ 模拟面试]
   ```
   当前这两个按钮若在选择简历后才出现，需改为**先显示按钮、选简历时触发确认**。

2. 点击「→ JD 备题」或「→ 模拟面试」前，弹出确认 Modal，内容预览：
   ```
   将带入以下内容：
   · 岗位：前端工程师
   · 公司：XX 科技
   · JD：（前 200 字预览）
   · 简历：[下拉选择简历库副本]  ← 模拟面试必选
   [确认带入] [取消]
   ```

3. 若当前会话无可用 JD，按钮置灰并 tooltip 提示"请先补充 JD"。

**验收**：从会话详情到进入备题/面试准备，操作步骤 ≤ 3 次点击。

### P0-4 · 模式标识统一展示

**文件**：`apps/web/src/preparation-panel.tsx`、`apps/web/src/interview.tsx`、`apps/web/src/intake.tsx`

**改动要求**：

在所有调用 AI 生成的功能入口处，统一展示一个轻量「模式标识」组件（建议复用现有 `Tag` 组件）：

```tsx
// 建议实现为独立组件 ModelModeTag
<Tag color={modelReady ? 'green' : 'orange'} icon={modelReady ? <CheckCircleOutlined /> : <ExperimentOutlined />}>
```

放置位置：
- **面试准备页**（`intake.tsx`）：页面标题行右侧
- **JD 备题页**（`preparation-panel.tsx`）：「生成题单」按钮左侧
- **模拟面试作答页**（`interview.tsx`）：侧栏顶部

**验收**：所有 AI 相关入口均有模式标识；演示分数旁保留现有"（演示）"标注。

## P1 批次：重要项

### P1-1 · 左侧菜单增加阶段说明文字

**文件**：`apps/web/src/module-navigation.tsx`

**改动要求**：

为每个菜单分组的 `label` 增加副标题，使用 Ant Design `Menu` 的 `group` 类型支持的 `label` slot（或在分组标签中内联小字）：

```tsx
const groups = [
  {
    label: '简历管理',
    subtitle: '第一步：整理你的简历',
    items: [...]
  },
  {
    label: '求职管理',
    subtitle: '第二步：发现岗位并投递',
    items: [
      { key: 'career', label: 'BOSS 求职' },
      { key: 'bossInbox', label: '已交换简历会话', hint: '可带入备题 & 面试' },
    ]
  },
  {
    label: '面试中心',
    subtitle: '第三步：备战与练习',
    items: [
      { key: 'preparation', label: 'JD 备题', hint: '支持从 BOSS 会话直接带入' },
      ...
    ]
  },
  {
    label: '学习训练',
    subtitle: '第四步：持续提升',
    items: [...]
  },
  ...
]
```

菜单项的 `hint` 以极小字（`<small style="opacity:.5">`）展示在标签右侧或下方，不影响点击区域。

**验收**：左侧菜单桌面端可见各组副标题；手机抽屉菜单同步展示；无障碍 `aria-label` 不受影响。

### P1-2 · 简历库卡片增加「带入面试」「带入备题」快捷操作

**文件**：`apps/web/src/resume-studio.tsx`

**改动要求**：

在简历库 JSON 副本的卡片操作区（现有「导出」「复制」「删除」等按钮旁），新增两个二级操作：

```
[导出 PDF]  [带入面试]  [带入备题]  [···更多]
```

- **带入面试**：导航到 `practice` 页并预填该简历（复用现有 `resumeId` 路由参数机制）
- **带入备题**：导航到 `preparation` 页并预填该简历信息

对于"已投递版本"（冻结的不可变 PDF 版本），在卡片右上角添加 `<Tag color="blue">已投递</Tag>` 冻结标记。

**验收**：简历库卡片一屏内可完成「预览 → 带入面试」或「带入备题」操作；投递版本有明确冻结标识。

### P1-3 · 面试报告每题旁增加「加入复习清单」按钮

**文件**：`apps/web/src/interview.tsx`（报告渲染区）或 `apps/web/src/report-priorities.tsx`

**改动要求**：

在面试报告的逐题 QA 展示中，每道题的操作区增加：

```
[加入复习清单]  ← 已加入则显示 [已加入 ✓]（可点击移除）
```

- 点击后调用现有 `saveReviews` 写入本机，无需跳转
- 若该题已在清单中，显示已加入状态并支持一键移除

**验收**：每题反馈旁有独立「加入复习清单」操作；操作后 Toast 提示并可在复习清单查看。

### P1-4 · 首页增加求职旅程引导区

**文件**：`apps/web/src/home-panel.tsx`

**改动要求**：

在现有 `<div className="workflow-steps">` 区域中，将三步卡片扩展为完整的九步旅程展示，或在三步卡片**上方**增加一条横向进度轨道组件：

```
求职全流程
[🔍找岗位] → [📄简历] → [✅审批] → [📨投递] → [🔄会话] → [📝备题] → [🎯面试] → [📊复盘] → [💪算法]
     ↑ 点击每步直接进入对应功能
```

实现建议：
- 使用 Ant Design `Steps` 组件（`direction="horizontal"`，`size="small"`）
- 每步 `title` 对应功能名，`status` 根据用户数据动态计算（有面试历史则 `finish`，有备题则高亮等）
- 点击每步调用 `navigate({ page: ... })`

在 `<div className="intro">` 的副标题中，将现有文案改为：
```diff
- 先整理简历，再匹配目标岗位，最后准备与复盘面试。
+ BOSS 找岗 → 简历制作 → 备题练习 → 模拟面试 → 复盘成长，一站搞定求职全流程。
```

**验收**：新用户打开首页 10 秒内能感知全链路流程；点击旅程步骤可跳转对应功能；现有三步卡片和近期面试列表保留。
