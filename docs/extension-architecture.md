# 面试扩展的归属与流转

当前 API 接受已授权资料和答案，事务保存会话与任务。Redis 只通知，Worker 对账 PostgreSQL。Agent 接收不可变任务快照，保留 jobId 的生成结果。Worker 以 revision 与 attempts 拒绝旧结果。模型连接 ID 属于浏览器 owner，密钥不进入任务。

新增计划采用一个有版本的会话聚合。纯规划函数拥有 HR 上限、编程资格、阶段预留、题量、难度与剩余环节的规则。API 保存规划快照、题库材料快照和搜索连接 ID。当前题在手动重规划时保留，变化只作用于剩余环节。进行中的生成任务不可修改。

上传 API 只做有大小限制的本地文本提取，返回可编辑预览。原始字节不长期保存，不引入对象存储或 RAG。题库资源属于 owner，自建及导入独立持久化。面试建立时固定题目快照，后续题库编辑不会修改旧练习。编程题以文本和代码作答，不执行不可信代码。

搜索凭据由 Agent 加密持有。查询只包含用户确认的岗位关键词，不能自动外发简历、联系方式或原作答。结果作为不可信资料，链接来自实际搜索响应。面试中的搜索快照与已有模型连接一样固定，失败不偷偷换供应商。

报告新增技术能力、沟通表达、综合素质。HR 的技术能力显示不适用。数值平均由服务端计算，逐题 QA 含原题、答案、原文依据、分维度评价和改进项。历史四维报告保持可读取。

替代形态为规范化的计划、问题、答案、评分表和读模型。它有更细的事务与统计能力，但会增加当前有限轮次应用的查询与迁移成本。当前优先保留已有状态聚合，用独立材料表固定题库快照。

设计审查已选聚合方案。规范化方案在题级历史上更好，但评分表和读投影增加当前产品的写入约束。已从另一方案保留稳定 questionId、不可变材料、计划 revision 和重规划 requestId。观察时长改为服务端 startedAt/presentedAt 推导，不接受客户端已答数量或 elapsed 参数。

严格模式的开场和反问也使用题库原文。用户选择问答题时，补入明确的内置流程题快照。问答或编程库存不足时停止并提示，不使用生成题填充严格题库。时间到达期限后，只评价已接受作答，不展示新题。

实现已连接 API、Worker、Agent 和 Web。真实文件、PostgreSQL、HTTP 夹具及 Chrome 的最终结果见 docs/evidence/extension-acceptance.md。真实付费模型及搜索账号未核验，不能由本地协议结果推断供应商质量或计费行为。
