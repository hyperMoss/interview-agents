# BOSS 聊天页读取依据

2026-11-11 的只读观察确认，聊天页使用 `chat-conversation` 容器，消息列表是 `chat-message > im-list`，消息有 `data-mid` 和双方、系统的方向类名。未选中聊天时，右侧显示 `chat-no-data`。本记录不包含真实聊天、公司名称或账号值。

## 标识来自已加载的组件数据

公开聊天前端的 [v5578 聊天组件](https://static.zhipin.com/fe-zhipin-geek/web/chat-new/v5578/static/js/chat.ce73f687.js) 与现场观察到的组件样式标识一致。它定义了当前选择、会话详情和岗位标题的绑定关系；[同版本入口](https://static.zhipin.com/fe-zhipin-geek/web/chat-new/v5578/static/js/app.ce73f687.js) 定义了求职者账号状态。

读取器只接受已识别的组件名称和结构标识，从现有状态中投影账号、会话、招聘方、岗位及详情入口。会话和岗位标识必须相互一致，公司和岗位名称还须匹配当前可见标题。不调用组件方法，不请求消息历史，也不读取 Cookie。版本或字段不匹配时拒绝保存。

Patchright 默认隔离执行环境不能访问页面组件对象。读取器仅对这一次状态投影使用安装版本支持的页面执行环境参数；其他浏览器操作不改变执行环境。实际 Chrome fixture 复现了默认环境下组件缺失，并验证切换后读取得到标识。

## 消息与 JD 的边界

消息正文来自当前可见 DOM。方向来自页面明确的类名，已读标记与隐藏内容被排除。非文本消息保留显式占位，不推测图片内容。简历交换必须有明确成功文本；请求或等待状态不能放行。

完整 JD 缺失时，沿用站点公开组件生成的同站岗位入口，在同一受管浏览器的新页读取。原聊天不导航；完成后核对原选择仍属于相同账号、会话和岗位。临时详情参数只用于本次读取，不进入 SQLite 快照。遇到验证或限制时保留现场并停止。

隔离 Chrome 测试使用合成组件对象和虚构资料，覆盖身份缺失、岗位冲突、可见标题冲突、交换请求未完成、消息方向、原选择保留和参数不落库。合成组件测试不能替代真实站点验收。

## 前十条会话

同版本入口定义原生 `labelId: 3` 的标签为“有交换”。聊天列表使用 `boss-list` 组件的 `curLabel$`、`loading$` 与 `fullList`；列表项由 `boss-item` 的 `boss.uniqueId`、`boss.encryptJobId` 与 `friend-content` 渲染。批量读取仅投影前十条标识，通过可见原生标签和列表项点击切换，不调用组件方法或站点私有接口。每条仍须通过当前聊天的账号、岗位、公司与简历成功证据校验。原生标签本身不能证明已交换简历。
