# 模型连接与面试恢复

状态：已实现；真实 PostgreSQL、OpenAI-compatible 本地 fixture 与 Chrome / Bun 全链路验证。

模型设置以编辑草稿、短探测、明确保存三个阶段工作。读取列表不要求预先知道模型名，模型列表不可用时可手动填写。探测和业务生成使用同一 Agent 出站策略。地址只允许 HTTP/HTTPS 根地址，不接受 URL 凭据、查询参数或片段；生产要求显式允许的主机名，并默认拒绝 HTTP 与私网。

连接由 Agent 持有，密钥以 AES-256-GCM 加密，内部 token 的域隔离 SHA-256 派生值作为密钥。API 只转发已授权请求，Worker 与业务记录只保存连接 ID、模型名与地址。业务数据库角色不能读取连接表；前端保存请求不进入 React Query mutation 缓存。默认连接 24 小时，显式选择后 30 天；过期记录定期清理。

每次保存生成新的连接 ID。之前连接在有效期内保留，确保已有面试继续使用原模型。恢复默认清除当前身份的全部连接；旧任务因此失败时明确提示重新配置。系统不把失败转换为另一个供应商或规则演示。

模型名和模式写入面试及逐题评分快照。部署方默认连接以内部 token 的 HMAC 绑定模式、模型、地址及凭据；新面试持有引用，地址或凭据变化时在供应商调用前拒绝旧任务。早期未包含引用的历史任务保留原有契约。真实评分必须提供当前答案中的原文依据，四维分数的平均值由服务端计算。示例模式、真实模式和未配置默认模型是明确的部署状态。

任务耗尽自动尝试后进入 failed，并保留原题与作答。用户可显式选择当前连接重试，使用新 job ID 和更高 revision；同一重试命令幂等。重试不会重新追加已完成回答，不能跨真实/演示模式切换。生成 payload 重新组装，避免恢复默认时残留旧连接 ID。

运行时启动时先完成 Mastra 存储初始化。临时模型 Agent 复用已初始化存储，不在生成 receipt 事务中重新执行数据库 DDL。浏览器测试发现过索引初始化等待同一生成事务的锁问题；修复后实际 Bun 请求及完整面试通过。

加密密钥不等于正式密钥管理系统。内部 token 轮换后，已有连接需重新保存。生产主机名允许列表和 DNS 检查需要与基础设施出站限制配合，不能替代网络层隔离。取消与崩溃恢复不保证供应商恰好计费一次。
