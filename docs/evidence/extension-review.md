# 扩展审查与修复

原生 GPT-6.1 Sol 的独立源码审查发现三个有效缺陷。主实现者核对复现后修复，没有直接采用代理修改。

| 触发条件 | 修复 | 验证 |
|---|---|---|
| 题库合法标题超过面试能力标签 100 单元限制 | 保留完整题库标题，限制派生能力标签 | 长中文标题通过完整严格模式面试 |
| 题库写入超过列表的 500 题上限 | 以 owner 事务锁限制可见总数，整批导入超额回滚；已有题仍去重 | 真实 PostgreSQL 的容量、最后一格并发创建和批量回滚 |
| 当前已到编程，延长时间重开较早的 QA 环节 | 保留当前题，关闭所有较早阶段的目标数量 | 五分钟进入编程后改为六十分钟，剩余仅编程与反问 |

新的独立 Sol 修复审查确认容量和阶段处理没有其他具体发现，但复现了 UTF-16 截断产生半个 emoji、PostgreSQL 拒绝 JSONB 的边界。能力标签截断现在移除末尾单独高代理字符。真实持久链验证 99 个 ASCII 字符加 emoji 的合法题库标题。又一轮新鲜 Sol 窄范围检查执行 18 个 Unicode 边界样本，没有剩余发现。它不替代主实现者的集成测试。

主实现者还通过合法 30 题长中文问答构造大于 2 MiB 的真实生成请求。内部 Agent 上限调整为 8 MiB，保持有界；运行时接受并完成该请求。结果见 [完整测试](extension-test-results.json)。

注释检查提出删除两条内部行为说明，并将尽力而为的操作直接表达为函数名。删除 2 条、恢复 0 条、重跑 0 次；`wakeWorkerBestEffort` 与 `tryClearInterviewDrafts` 已替换旧名，没有改变应用行为。无保留约束或未处理编码建议。安装的 comment-sicko 引用缺失，使用找到的备份角色说明，只读检查后由主实现者改动；未修改全局技能。

不同家族 GPT-6 Luna 审核决策记录及本次工作摘要，要求补记已经发生的浏览器失败。已保存失败 JSON 并追加后续通过行；旧 56 项 / 4 场验收标为历史。权限的早期宽泛授权被自动审批拒绝，随后仅授权四张新增表，[实际授权元数据](extension-table-grants.json) 可核对。没有剩余审批请求。

Claude 子进程实际报告未登录，Grok CLI 未安装。Astra 尝试因工作区额度中断。上述都没有计为通过，也没有形成跨供应商一致审查结论。

## 原则对应的具体选择

| 原则 | 改变的选择 |
|---|---|
| Model the Domain | 以版本化计划、阶段和结构化 QA 表达面试，状态约束由业务层拥有 |
| Foundational Thinking | 先建立计划、题库与搜索契约，再接 IO、持久任务和页面 |
| Boundary Discipline | 在文件、配置、网络及模型输出边界校验，规划使用纯函数 |
| Type System Discipline | 新计划与旧报告明确区分，技术维度允许不适用，外部输入经 schema 解析 |
| Separate Before Serializing Shared State | 搜索和模型凭据由独立 Agent 持有，题库操作按 owner 事务锁串行化 |
| Sequence Work into Verifiable Units | 分别验收规划、文件、题库、搜索、持久链和页面后再接下一层 |
| Prove It Works | 使用真实合成文件、PostgreSQL、HTTP 协议、公开 LeetCode 和 Chrome 验证产物 |
| Never Block on the Human | 在既有授权内继续可逆实现，不把可运行的边界问题交给用户猜测 |

剩余注意项为真实付费模型和搜索账号未核验、无 OCR / RAG / 语音 / 代码执行，以及本地个人应用未验收公开生产部署。具体范围见 [扩展验收](extension-acceptance.md)。
