## 吞吐检查

- Blocking first steps. 保留现有未提交界面改动，先修改 spec 并生成解析计划；确认现有模型和题库边界。
- Independent workstreams. GitHub 方案调研与本地架构检查可独立进行。契约确定后各层按依赖实现。
- Shared mutable state. 生成不写业务表；用户确认后由题库模块在现有 owner 事务中批量入库。
- Smallest safe decomposition. 新能力只有一个代码 owner，避免契约、提示词与题库入库规则出现多个写入者。

## 现有运行流程

浏览器通过 NestJS 的签名匿名身份访问接口。模型配置由 Agent 加密保存，API 只获取可公开的模型描述。面试任务经 PostgreSQL、Worker 调用 Agent；题库写入由 API 的 QuestionBank 负责。面试创建时冻结题库快照，严格模式保留原题。

JD 预生成属于面试前的准备任务。备题结果先返回当前浏览器，用户可编辑、导出、选择入库。它不创建面试、不评分、不自动写题库，也不自动触发联网搜索。生成失败时保留用户输入和上一份题单。

## 验收要求

- 仅提供岗位与 JD 即可生成题单，不强制填写简历。
- 每个岗位要求附 JD 连续原文，必备项与加分项分开；问题引用合法的要求编号。
- 题量、难度与轮次受控，HR 和非技术岗只生成行为问答。
- 真实模型遵守现有连接选择，演示输出清楚标识。
- 用户编辑题面与答案要点后批量入库，重复保存不产生重复题目，失败不留下半批数据。
- 已入库题目可带入严格模式练习，保持原题；其他身份无法读取。
- 页面刷新保留本标签页草稿，Markdown 导出包含原文依据与问题。
