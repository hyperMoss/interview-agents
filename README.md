# 面试练习室

中文 AI 模拟面试应用。上传或填写真实简历与目标岗位，按时长、回答长度、候选人级别和轮次规划面试。支持题库、联网资料、动态重规划、技术能力 / 沟通表达 / 综合素质评估与逐题 QA 复盘。模型连接、历史记录、草稿恢复、失败重试、重新练习、报告导出与删除均可在应用内操作。

React 19 / Vite / TypeScript / TanStack Query；NestJS API；PostgreSQL / Drizzle；独立 Hono / Mastra / Bun Agent；Nest Worker / BullMQ / Redis。安装版本由 `pnpm-lock.yaml` 锁定。

## 本地启动

需要 Node ≥22.16、pnpm 12.11.2、Docker。命令从仓库根目录执行，示例凭据仅用于本地开发。

```sh
pnpm install --frozen-lockfile --ignore-scripts
pnpm runtime:setup
cp .env.example .env
docker compose -f infra/compose.yaml up -d --wait
pnpm dev
```

打开 [面试练习室](http://localhost:5173)。Web 5173、API 3000、Agent 4111；开发数据库 55439、Redis 56389。启动前确认这些端口可用。保留原有 `.env` 时不要覆盖它。

首次启动会初始化数据库。已有数据库需要管理员执行新增迁移，然后确认 Agent 角色拥有 `agent_runtime` 表权限；迁移命令为 `MIGRATION_DATABASE_URL=管理员连接地址 pnpm db:migrate`。当前本地数据库已应用三份迁移。已有库需要对新增的 `app.bank_questions`、`app.interview_materials`、`app.interview_commands` 授予 app 角色 CRUD，对 `agent_runtime.search_connections` 授予 agent 角色 CRUD。只授权对应表，不扩展既有角色的其他权限。

## 开始 AI 面试

1. 点击左侧 **模型设置**，填写 OpenAI-compatible API 根地址、API Key 和模型名。完整 `/chat/completions` 地址也会规范化为根地址。本地模型地址指 Agent 所在机器。
2. 可先 **读取模型列表** 或手动填写模型名，再 **测试连接**。短探测只验证连通性，可能产生供应商费用。
3. 点击 **保存并启用**。默认连接有效 24 小时；勾选后保留 30 天。更新连接需要重新填写密钥。
4. 上传 PDF / DOCX / TXT / Markdown 简历，检查和编辑提取预览后使用；也可直接粘贴简历。填写岗位、JD 和练习重点。
5. 选择时长、回答长度、实习 / 校招 / 社招、一面 / 二面 / HR 面及题库模式。预览题量与环节后开始。
6. 逐题回答后查看反馈；完成后导出 Markdown 复盘报告或 JSON 记录，也可以用相同资料再练一次。

默认提供明确标识的规则演示，便于无密钥体验流程；演示评分不代表专业能力。启用自带连接后，新面试调用所选 AI 模型。设置变更只影响新面试，已有面试保留模型快照。

资料和未提交作答草稿暂存在当前标签页，刷新后恢复；已提交的面试与任务保存在服务端，关闭页面不会丢失已接受的作答。历史可按岗位或状态查找，展示最近 50 场。

模型生成失败时，原题与作答仍可查看。检查模型设置后，显式使用当前连接重试本轮；不会重复追加已接受的回答。也可取消或删除练习。过期或已清除的连接需要重新启用；系统不会偷偷降级到演示或其他供应商。

## 上传、规划、题库与搜索

简历最多 5 MB，在本地服务的有超时与 V8 堆内存上限的独立进程解析。PDF 提取前 20 页，扫描 PDF 需要先 OCR；DOCX 支持文本提取，旧 DOC 需转换。预览最多 64000 字，提交简历最多 16000 字。应用不长期保存原始文件，确认后的文本会随面试记录保存。

总时长可设 5 至 120 分钟。HR 面强制最多 30 分钟，并禁用编程题。题量计算包含回答长度、候选人级别和面试轮次，预留开场、问答、编程和反问。每次提交后，服务端根据第一题计时、已完成环节和最近三次 QA 耗时重规划。等待作答时可调整总时长与后续回答长度，当前题、已完成 QA 和草稿保留。刷新不重置计时。最多 30 题，时间到达后只评估当前已接受回答，不再展示新题。

编程题只在求职者模式、技术岗且非 HR 面启用。按岗位方向与候选人难度从题库选原题。提交代码与思路供模型评价，服务端不执行代码。面试官演练使用同一问答流程检验提问和评估，禁用编程环节。

题库管理支持自建、编辑、删除、检索、公开 LeetCode 链接导入与 JSON 批量导入。JSON 格式可在页面查看，每次最多 100 题与 5 MB，按地区与 slug 去重。公开链接不使用账户 Cookie，付费题不导入；上游受限时可用 JSON。每个身份最多 500 题，包含内置题。满额会明确拒绝新增，批量导入超额时整批回滚，重复题仍跳过。选择题目后会补入内置开场和反问，之后按岗位与难度筛选。每场固定题库快照，编辑题库不改变旧面试。

- 严格模式保持原题，题量受匹配库存限制。
- 混合模式交替使用原题和生成 QA。
- 灵活改编模式按候选人难度调整题库材料，也可生成 QA。

开场、反问和编程始终使用原题。页面显示问题来源，结构化记录保留题目 ID、题库 ID、阶段、难度、原答案、原文依据和维度评分。HR、非技术岗、开场和反问的技术能力显示不适用。汇总分由服务端计算；历史四维报告仍可读取。

在 **联网搜索** 中选择 Tavily 或 Firecrawl v2，填写根地址与密钥，可测试后保存。每场需单独启用并确认 2 至 200 字关键词。只发送确认查询，不自动发送简历、JD 或答案。首次实际取得的来源固定用于本场并进入报告。搜索失败会显示错误，可以重新配置连接，或明确关闭本场搜索后重试。清除连接不删除已经取得的来源。

## 配置与数据归属

部署方也可在 Agent 环境配置 `MODEL_MODE=live`、`LLM_MODEL=provider/model`、`LLM_API_KEY`，兼容接口可设置 `LLM_BASE_URL`。仅使用用户自带连接时可配置 `MODEL_MODE=disabled`，未启用连接前禁止开始。

`CUSTOM_MODELS=auto` 和 `ALLOW_LOCAL_MODELS=auto` 在开发环境开放，在生产环境关闭。生产自带接入需要显式 `CUSTOM_MODELS=on`、`MODEL_ALLOWED_HOSTS` 主机名允许列表及 HTTPS；默认拒绝私网出站。仅在受控本地部署需要时开放本地模型访问。

模型与搜索 API 密钥经业务 API 授权转交 Agent，保存在独立 Agent 数据库的 AES-GCM 加密字段中；业务数据库角色不能读取它。浏览器持久存储、面试任务、报告与导出不包含密钥。清除连接会删除当前身份全部自带连接，也会使旧面试的对应连接失效。更换内部服务 token 后，已有加密连接需重新保存。

记录属于签名浏览器身份，没有正式账号登录或跨设备同步。共享设备使用后，删除练习并清除模型与搜索连接。清除浏览器 Cookie 会失去旧身份访问能力。删除练习会通过持久清理任务清除派生生成结果。

取消使会话终态稳定，但不保证第三方停止计费。当前限额是每个浏览器身份每日最多 20 场保留会话；删除会话会降低计数，不应当作公开服务的全局成本控制。

搜索的部署开关为 `SEARCH_ACCESS`、`SEARCH_ALLOWED_HOSTS` 和 `ALLOW_LOCAL_SEARCH`。开发默认开放，生产默认关闭；生产需显式开放并设置允许主机及 HTTPS。搜索连接同样默认 24 小时，可选 30 天。

## 验证

```sh
pnpm build
docker compose -f infra/compose.test.yaml up -d --wait
RUN_INTEGRATION=1 pnpm test
pnpm test:e2e
docker compose -f infra/compose.test.yaml down --volumes
```

集成测试使用独立临时数据库 55440。Chrome 浏览器测试需要 `pnpm dev` 已启动，使用独立测试身份与本地模型协议 fixture，不调用真实付费供应商。测试使用默认开发端口和配置。

已通过严格类型检查、生产前端构建和扩展测试；最终结果见 [扩展验收记录](docs/evidence/extension-acceptance.md)。公开 LeetCode 网络验收使用 `RUN_PUBLIC_IMPORT=1 pnpm test:e2e` 显式启用。真实付费模型与搜索账号、外部计费和评分质量仍需实际连接核验。当前支持本地简历提取和联网搜索，RAG、语音及代码执行未启用。

生产前端产物位于 `dist/web`，目前本地通过 Vite 运行。公开部署还需 HTTPS 反向代理、按服务注入凭据、备份与全局成本限制；完整生产镜像组合尚未验收。
